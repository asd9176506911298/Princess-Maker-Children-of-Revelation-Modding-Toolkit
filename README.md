# Princess Maker: Children of Revelation — TableData & Bundle Tool

**English** | [繁體中文](README.zh-TW.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

A small Windows GUI tool for **Princess Maker: Children of Revelation** (Steam). It decrypts the game's AssetBundle, extracts and edits the encrypted `TableData`, and lets you keep your edits across game updates with patch files.

UI languages: 繁體中文 / 简体中文 / English / 日本語 / 한국어 (switch from the top-right corner).

## Features

- **Bundle decrypt** — decrypts `packedassets_assets_all_*.bundle` in place (a `.bak` backup is made first).
- **TableData extract / edit** — pulls `TableData` out of `resources.assets`, decrypts it, and builds a SQLite database plus one JSON file per table.
- **Database browser** — search tables, filter rows, double-click a cell to edit, read-only SQL box. Edits keep their original types (numbers, booleans, lists).
- **Re-encrypt & output** — writes `TableData_modified.txt`, which you import back into `resources.assets` with [UABEANext](https://github.com/nesrak1/UABEANext). The tool itself never overwrites `resources.assets`.
- **Patch files** — save your edits as a small patch and re-apply them after the game updates.

## Basic workflow

1. Pick your game folder (the one containing `PrincessMakerKaren_Data`) and press **Auto detect**.
2. **Bundle Decrypt** tab → *Decrypt Bundle* (only needed once).
3. **TableData** tab:
   1. *Extract & decrypt from resources.assets*
   2. *Build database + export JSON*
4. **Database Browser / Editor** tab → click a table, double-click a cell to edit, press *Save changes*.
5. **TableData** tab → step 3 *Re-encrypt and output TableData_modified.txt*.
6. Open `resources.assets` with UABEANext, import `TableData_modified.txt` into the `TableData` asset, and save.

You can also edit the JSON files in `tables/` directly, then press *Reload from tables*.

## Keeping your edits after a game update

Game updates replace `TableData`, so edits made on the old data would be lost. Use a patch:

1. **Create patch (save my edits)** — stores only the differences from the original data, matched by each row's unique ID column.
2. Update the game, then redo steps 1 and 2 (extract + build database).
3. **Apply patch (restore my edits)** — applies the patch to the new data.
4. Step 3 → output → import with UABEANext again.

If the game changed a cell you had also edited, you are asked whether to overwrite it with your value or keep the game's new value. Anything that cannot be matched (row removed, column renamed, table gone) is listed in `patches/apply_report_*.txt` instead of being silently dropped.

Safety net: step 2 automatically saves your current edits as `patches/auto_before_reexport_*.json` before it overwrites `tables/`.

## Files created next to the exe

| Path | Purpose |
|---|---|
| `TableData.dec.bin` | decrypted TableData |
| `TableData.db` | SQLite view used by the browser |
| `tables/` | one JSON per table (your editable copy) |
| `tables_orig/` | untouched copy used as the baseline for patches |
| `patches/` | patch files and apply reports |
| `TableData_modified.txt` | final output to import with UABEANext |
| `pm_tool_settings.json` | language and last game folder |

## Build the exe yourself

Put `PrincessMakerTool.py`, `requirements.txt` and `build.bat` in one folder and double-click `build.bat`. The result is `dist\PrincessMakerTool.exe`.

## Notes

- Windows only (the build script and paths target the Windows Steam version).
- Always keep a backup of your game files. Steam → *Verify integrity of game files* restores them.
- Unsigned one-file exes are sometimes flagged by antivirus software or SmartScreen. Build it yourself from source if you prefer.
- Tables without a unique ID column fall back to row-position matching in patches, which is less reliable after updates.
